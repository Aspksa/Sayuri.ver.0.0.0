# Sayuri Yukishiro

**Релиз:** v0.4.1 · **Ядро:** v0.1.0 · **В разработке:** v0.5.0

Переносимая персональная платформа. Работает с любого носителя: внутреннего диска, внешнего диска или флешки — без установки и без настройки путей.

## Запуск

Запустите **«Sayuri Yukishiro.bat»**.

Дальше всё происходит само:

1. определяется корень проекта от расположения файла — без привязки к букве диска;
2. ищется Python: портативный в `runtime\python`, затем `.venv`, затем системный;
3. если носитель защищён от записи, данные переносятся в профиль пользователя;
4. выполняется диагностика готовности;
5. поднимается ядро, занимается свободный порт;
6. **сайт открывается в браузере автоматически.**

7. **окно сворачивается в область уведомлений** — значок появляется у часов.

Повторный запуск `.bat` не создаёт второй экземпляр — он открывает уже работающий сайт.

## Обновление через сайт

Раздел **«Обновление проекта»** на сайте: проверка, план и установка обновления из GitHub.

1. **Проверка** — читает репозиторий, ничего не меняет. Показывает проверки готовности со значками и объяснением, что делать при отказе.
2. **План** — «было и стало» по каждому компоненту, список коммитов и изменённых файлов.
3. **Установка** — стадиями, с прогрессом: проверка → резервная копия → загрузка → установка → проверка после установки → готово.

Обновление не может сломать проект:

- только **fast-forward** от источника текущей ветки, никаких reset и force;
- **свои правки** в рабочем каталоге блокируют обновление, а не перезаписываются;
- **резервная копия** базы и файлов состояния до изменений;
- **проверка новым кодом** отдельным процессом: протокол, компиляция, тесты;
- **откат** при провале проверки: файлы возвращаются, база восстанавливается из копии.

Если источник ушёл вперёд между проверкой и установкой, установка отклоняется: иначе вы получили бы версию, план которой не видели.

Подробности и обоснование решений: `docs/UPDATE_SERVICE.md`.

## История обновлений

Раздел **«История»** — таймлайн версий из `UPDATE_LOG.md`: дата, статус, изменения с их ID, сгруппированные по типам (новые возможности, исправления, улучшения, архитектура), результаты проверок и коммит. Плюс список установок на этом носителе: что на что менялось, был ли откат.

## Значок у часов

После запуска окно убирается в область уведомлений, а ядро продолжает работать отдельным фоновым процессом.

| Действие | Что делает |
|---|---|
| двойной клик по значку | открывает сайт |
| **Открыть Sayuri** | открывает сайт |
| **Состояние** | показывает версию, службы, состояние базы и тип носителя |
| **Показать окно** / **Скрыть окно** | возвращает и убирает окно запуска |
| **Перезапустить ядро** | мягко останавливает и поднимает ядро заново |
| **Выход** | мягко останавливает ядро и убирает значок |

Подсказка значка обновляется каждые 5 секунд. Если состояние меняется — система стала активна, появились замечания, ядро перестало отвечать — всплывает уведомление.

**Выход всегда пробует мягкую остановку** по токену: ядро само закрывает базу, снимает `endpoint.json` и останавливает службы. Принудительное завершение применяется только если ядро не ответило за 15 секунд — иначе на съёмном носителе остался бы незакрытый файл базы.

Отключить режим трея: `-NoTray` (ядро останется в окне) или `SAYURI_TRAY=0`.

Иконка собирается из исходника: `python scripts/make_icon.py`. Для 16 px используется упрощённая отрисовка без тонких ответвлений — иначе снежинка в трее превратилась бы в кашу.

Адрес по умолчанию: `http://127.0.0.1:8765`. Если порт занят, берётся свободный, и фактический адрес записывается в `data/runtime/endpoint.json`.

## Ядро v0.1.0

- **Переносимость** — никакой привязки к букве диска; тесты это проверяют.
- **Политика носителя** — WAL на локальном диске, DELETE с `synchronous=FULL` на съёмных, сетевых и синхронизируемых путях.
- **База с миграциями** — объявленный список миграций; база новее сборки отклоняется, а не портится.
- **Жизненный цикл служб** — запуск в порядке регистрации, остановка в обратном, откат уже запущенных служб при сбое.
- **Конфигурация** — значения по умолчанию, `config/system.json`, переменные окружения.
- **Журнал** — структурированный, с ротацией файлов.
- **Шина событий** — сбой одного обработчика не отменяет доставку остальным.
- **Фоновые задачи** — ограниченная история, освобождение futures, фиксация прерванных задач после перезапуска.
- **Контрольные точки** — обязательный `next_action`, восстановление без автоматического повторения действий.
- **CoreAPI** — единственный интерфейс ядра для будущих модулей.
- **Диагностика** — Python, носитель, хранилище, интерфейс, база, ядро, браузер, экземпляр, порт, Git.

## Module Runtime v0.4.0

Модули живут в `modules/<module_id>/` и описываются строгим `module.json`.
Runtime обнаруживает их без импорта, проверяет SemVer и зависимости, применяет
миграции отдельной SQLite-базы, выдаёт только разрешённый `ModuleAPI`, запускает
в dependency order и останавливает в обратном порядке.

Ошибка модуля не обязана валить ядро: модуль получает `failed/blocked`, а
система — `degraded`. Ручной start/stop доступен через локальный tokenized API.
Версии модулей входят в план обновления «было → стало».

Важно: permissions ограничивают capability API, но in-process Python не является
OS-песочницей. Недоверенные модули потребуют отдельного process isolation слоя.

Подробный контракт: `docs/MODULE_RUNTIME.md`.

## Статусы

Каждая проверка и каждый этап запуска показываются одним значком:

| Значок | Unicode | ASCII | Значение |
|---|---|---|---|
| успех | `✓` | `+` | проверка пройдена |
| замечание | `!` | `!` | работать можно, но есть ограничение |
| отказ | `✗` | `x` | запуск невозможен |
| этап | `▸` | `>` | параметр окружения |

Пример вывода:

```

  ╰──────────────────────────────╯

  ▸ Данные     E:\Sayuri\data

  [✓] python        Python 3.11.9; требуется >= 3.11
```

## Локальный API

Только петлевой интерфейс.

| Эндпоинт | Содержимое |
|---|---|
| `GET /api/health` | краткое состояние |
| `GET /api/core` | состояние ядра и служб |
| `GET /api/core/jobs` | фоновые задачи |
| `GET /api/core/recovery` | незавершённые задачи с `next_action` |
| `GET /api/core/events` | последние события |
| `GET /api/core/config` | действующая конфигурация |
| `GET /api/modules` | manifests, dependency graph, lifecycle и health модулей |
| `GET /api/system` | полная сводка: носитель, схема, адрес, запуски |
| `POST /api/modules/<id>/start` | запустить модуль, требует токен |
| `POST /api/modules/<id>/stop` | остановить модуль, требует токен |
| `POST /api/shutdown` | мягкая остановка, требует токен |
| `GET /api/session` | токен для изменяющих вызовов, только локально |
| `GET /api/update` | состояние обновления, компоненты, источник, копии |
| `GET /api/update/plan` | последний построенный план |
| `GET /api/update/progress` | стадии установки и процент |
| `GET /api/update/history` | история версий и установок |
| `POST /api/update/check` | проверить обновление, требует токен |
| `POST /api/update/apply` | установить обновление, требует токен |

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `SAYURI_PORT` | порт локального сервера |
| `SAYURI_AUTO_PORT` | брать свободный порт, если штатный занят |
| `SAYURI_OPEN_BROWSER` | открывать сайт автоматически |
| `SAYURI_DATA_DIR` | каталог runtime-данных |
| `SAYURI_SQLITE_JOURNAL_MODE` | `WAL` или `DELETE` |
| `SAYURI_LOG_LEVEL` | уровень журнала |
| `SAYURI_CORE_MAX_WORKERS` | число фоновых потоков |
| `SAYURI_JOB_HISTORY_LIMIT` | предел истории задач в памяти |
| `SAYURI_RECOVERY_ENABLED` | включить восстановление |
| `SAYURI_ASCII` | значки и рамки только ASCII |
| `SAYURI_COLOR` | принудительно включить или выключить цвет |
| `NO_COLOR` | отключить цвет (общепринятая договорённость) |
| `SAYURI_TRAY` | включить или отключить режим трея |
| `SAYURI_TRAY_HIDE_CONSOLE` | сворачивать окно при запуске |
| `SAYURI_TRAY_POLL_SECONDS` | период опроса состояния в трее |
| `SAYURI_MODULES_ENABLED` | включить или отключить Module Runtime |

## Требования

Python 3.11+. Для запуска через `.bat` — Windows PowerShell. Ядро и тесты работают также на Linux и macOS.

## Разработка

Любое изменение обязано следовать `docs/UPDATE_PROTOCOL.md` и начинаться с чтения `AGENTS.md`, `UPDATE_IDS.json`, `UPDATE_LOG.md` и `PROJECT_STATE.json`.

```
python scripts/validate_update_protocol.py
python scripts/check_powershell.py
python -m compileall -q src scripts tests
PYTHONPATH=src python -m unittest discover -s tests
```

Завершённая версия сливается в `main` и отправляется: `main` — то, что отдаёт «Download ZIP», поэтому непрослитая версия для пользователя недоступна. Порядок — в `AGENTS.md`.

Архитектура: `docs/ARCHITECTURE.md`.
