# ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ ОБНОВЛЕНИЙ ПРОЕКТА

Этот протокол обязателен для всех изменений Sayuri Yukishiro.

## Версии

Формат версии: vMAJOR.MINOR.PATCH.

- MAJOR — крупное изменение архитектуры или несовместимое изменение.
- MINOR — новый модуль, новая функция или крупное расширение.
- PATCH — исправление, улучшение, оптимизация или небольшое изменение.

Нельзя изменять проект без привязки работы к текущей development_version или новой версии.

## Уникальные ID

| Префикс | Назначение |
|---|---|
| CHG-NNNN | каждое отдельное изменение |
| FEAT-NNNN | новая функция |
| BUG-NNNN | дефект, регистрируется до исправления |
| FIX-NNNN | исправление, обязано ссылаться на BUG-NNNN |
| IMP-NNNN | улучшение |
| ARCH-NNNN | архитектурное изменение |

Номера никогда не сбрасываются и не используются повторно.

## Журнал и реестр

Главный журнал: UPDATE_LOG.md.
Машинный реестр счётчиков: UPDATE_IDS.json.

Перед выдачей нового ID необходимо прочитать оба файла и использовать следующий свободный номер.

## Обязательная последовательность

```
задача -> ID -> изменение -> проверка -> версия -> журнал -> commit -> next_action
```

Для разработки используется development_version. Релизная версия становится текущей только после успешных проверок.

## Проверки

Каждая версия обязана фиксировать результаты проверок. Разрешены статусы PASS, FAIL, PENDING, NOT_CONFIGURED и NOT_APPLICABLE. Нельзя записывать PASS, если проверка реально не выполнялась.

Если для репозитория настроен GitHub Actions, implementation commit сначала публикуется в ветку разработки. Версию нельзя переводить в `completed` и нельзя продвигать в `main`, пока обязательный workflow для этого commit не завершился успешно на всех заявленных платформах. Локальный PASS не заменяет красный CI.

## Commit

Поле Commit в журнале содержит SHA основного implementation commit, прошедшего проверки. Отдельный metadata commit может финализировать журнал после проверки implementation commit; это устраняет невозможную самоссылку commit SHA на самого себя.

## Следующий агент

Перед любым изменением следующий агент обязан прочитать:

1. AGENTS.md
2. docs/UPDATE_PROTOCOL.md
3. UPDATE_IDS.json
4. UPDATE_LOG.md
5. PROJECT_STATE.json

После этого агент продолжает существующую нумерацию и next_action.

## Запреты

1. Никаких скрытых изменений.
2. Никаких повторных ID.
3. Никаких FIX без BUG.
4. Никаких незарегистрированных новых функций.
5. Никаких завершённых версий без проверок.
6. Никакого перехода к следующему этапу без next_action.
